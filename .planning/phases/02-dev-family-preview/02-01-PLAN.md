## Phase Goal

**As a** family product owner, **I want to** use a safe Family Preview of our week on my phone, **so that** I can try changes without risking Home.

<objective>
Slice 1 of the phase, for the developer: the seed tool that every later command drives. It brings a real Home Assistant up over HTTPS from a local CA, onboards it, promotes the HTTP config and names it "Family Hub DEV", and it refuses anything that is not a loopback Dev or Preview. It also keeps card caches fresh after edits (`resources-sync`, which plan 02-02's `scripts/dev-cards` calls). The plan ends with the package-legitimacy checkpoint that gates every pip install later in this phase.

Purpose: DEV-01 (the Home Assistant half of the one Dev command; plan 02-02 adds compose and `scripts/dev-up` in the same wave) and DEV-02 (the resource refresh behind `scripts/dev-cards`). It also lays down the shared pieces every later plan uses: the environment table (`tools/seed/envs.py`), the CA-pinned HA client, the per-environment credential store, the config-flow driver and the `LiveHA` test harness that runs a real HA 2026.10.4 in this sandbox.
Output: dev/config-template/configuration.yaml, scripts/make-certs, the tools/seed package skeleton with bootstrap and resources-sync, live and unit tests.

Decisions implemented: D-01 (Dev's own identity "Family Hub DEV" and port 8130 in the environment table), D-04 (host-agnostic: the seed tool reads host values only from environment variables), D-06 (HTTPS from day one, local CA), D-31 (core settings from the host env file). Discretion used: name-constrained openssl root CA instead of mkcert (D-06 allows either); the seed tool runs inside the pinned HA image on the laptop (plan 02-02's `fh_seed`: `docker run ... python3 -m tools.seed`), so the laptop needs no Python installs and the tool uses exactly the aiohttp 3.14.5 and PyYAML 6.0.3 that HA 2026.10.4 ships; `configuration.yaml` has no `homeassistant:` core block, because any core key there switches HA's config source to YAML (homeassistant/core_config.py), so the seed owns `location_name` and the D-31 keys through `config/core/update`.
</objective>
