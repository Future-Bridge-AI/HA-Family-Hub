1. **tools/seed/calendar_tags.py** (pure, stdlib only):
   - `marker(env, key)` returns env.marker_prefix + key; the key must match `^[a-z0-9-]+$`, else ValueError.
   - `parse_marker(description, env)` returns the key from the first description line that equals env.marker_prefix followed by a valid key, and None otherwise. The whole line must match: no leading or trailing text.
   - `matches(event, env, calendar, allowed_calendars, window_start, window_end)` is True only when all hold:
     - the summary starts with exactly env.tag (case-sensitive, including the trailing space);
     - parse_marker finds a key;
     - the event has no rrule and no recurrence_id;
     - start is a datetime or date with window_start <= start < window_end (all-day dates compared as local midnight);
     - calendar is in allowed_calendars.
   - Module docstring: why each condition exists, and that this function is the only gate before a delete.
2. **tools/seed/events.py**:
   - `CalendarSlot(person, entity_id, writable=True)` and `DesiredEvent(key, entity_id, summary, description, start, end, all_day)`.
   - `window(today)` returns (monday, monday + 14 days); `delete_window(today)` returns (monday - 28 days, monday + 14 days).
   - `plan_week_events(slots, env, today)` builds the desired list from two fixed weekly templates over the writable slots:
     - this-week template: every day has an all-day or morning event and an event at 16:00 or later; Saturday has 4 events; Friday has one all-day event; one event (Wednesday "Family movie night" 18:30) goes on two members' calendars; each day leaves at least one member without events;
     - next-week template: the same keys minus Sunday's events, and only one event on Tuesday;
     - titles from UI-SPEC S5 (School drop-off, Dentist, Football practice, Piano lesson, Family movie night, Grandma visits);
     - summary = env.tag + title; description = the marker line;
     - key = `<iso-year>w<iso-week>-<weekday 1-7>-<slot>-<person-slug>`;
     - sort by (start, entity_id, key).
   - `diff(desired, existing, env, allowed, today)` returns create / delete / keep lists:
     - delete = existing events that pass matches() over delete_window and whose key is not desired, plus duplicate keys after the first, plus events whose key is desired but whose start or summary differ (then re-created);
     - existing events that fail matches() are never in any list.
   - `sync(client, token, slots, env, today, apply)`: read each slot's events with GET /api/calendars/<entity>?start=&end= over delete_window; delete through WS `calendar/event/delete {entity_id, uid}` (plus recurrence_id only if present, which matches() already excludes); create through service `calendar.create_event` (start_date_time/end_date_time, or start_date/end_date for all-day). Print `CREATE|DELETE|KEEP <entity> <start> <summary>` lines, then a summary line `events: create N, delete M, keep K (dry run)` or `(applied)`.
   - `clean(...)` treats the desired set as empty, so every matching event in delete_window is deleted. Both default to dry run.
   - CLI via `if __name__ == "__main__"`: `python -m tools.seed.events --target {dev,preview} [--base-url] [--ca] [--secrets-dir] {plan,sync,clean} --calendar ENTITY=PERSON[:ro] (repeatable) [--today YYYY-MM-DD] [--apply]`. It logs in as the tooling admin from credentials-<env>.json, reuses envs.base_url's loopback guard (exit 2), and exits 1 on SeedError.
