## Phase Goal

**As a** family product owner, **I want to** use a safe Family Preview of our week on my phone, **so that** I can try changes without risking Home.

<objective>
Slice 2 of the phase, for the developer: the host layer around the seed tool. `scripts/dev-up` is the one command that starts Dev in Docker on the pinned image, on its own loopback port with the working copy's integration mounted read-only, and hands over to the seed tool from plan 02-01. `scripts/dev-cards` and `scripts/dev-restart` make card and Python edits show up, and `.gitattributes` keeps every script runnable from a Windows-side clone.

Purpose: DEV-01 (the one command) and DEV-02 (the edit loop). It also lays down `scripts/lib.sh`, which every later script (deploy, reset, refresh, doctor) sources, and the single gitignored host env file (D-04).
Output: .gitignore and .gitattributes rules, dev/host.env.example, dev/compose.yaml, dev/compose.dev.yaml, and the scripts lib.sh, dev-up, dev-cards, dev-restart and dev-down.

Decisions implemented: D-01 (Dev's own container, volume and port 8130), D-04 (host-agnostic tooling, one gitignored host env file), D-06 (the local CA certificates mounted for HTTPS from day one), D-31 (core settings come from the host env file and reach the seed tool through `--env-file`). Discretion used: the seed tool runs inside the pinned HA image (`docker run ... python3 -m tools.seed`), so the laptop needs no Python installs.
</objective>
